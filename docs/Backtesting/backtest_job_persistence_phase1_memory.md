# 回测任务持久化 Phase 1 Memory

## 任务总结

- 新增 `backtest_tasks` 与 `backtest_task_events`，回测任务状态、结果、参数、进度和事件流写入 SQLite。
- `BacktestJobManager` 保留线程池执行，但查询优先兼容内存任务，内存缺失时可从 SQLite 恢复。
- `run_backtest` 支持 `progress_callback`，日线和分钟执行器每处理一个候选回调一次进度。
- API 新增任务历史与事件流：
  - `GET /api/backtest/tasks`
  - `GET /api/backtest/tasks/{task_id}/events`
- 前端回测页新增任务进度条、当前代码、最近任务历史、历史任务查看和最近事件摘要。

## 验证证据

- 后端编译：`python -m py_compile ...` 通过。
- 回测相关测试：`23 passed`。
- 前端构建：`npm run build` 通过；仅保留 Vite 大 chunk 提示。

## 当前边界

- 任务结果已经持久化，但执行线程仍是单进程 `ThreadPoolExecutor`。
- 支持查看历史任务与进度事件，暂不支持取消任务。
- 进度按候选处理回调；更细的分钟线内部撮合进度暂未展开。

## 下一步计划推导

1. 增加“取消任务”能力：避免误点大区间回测后只能等待运行预算耗尽。
2. 增加回测任务详情页或抽屉：历史任务可展开参数、交易明细、事件流和结果摘要。
3. 继续完善资金与仓位模型：从单笔收益统计升级为组合资金曲线、现金占用、仓位上限、同日多信号去重。
4. 再做交易规则扩展：涨跌停可成交边界、停牌、手续费最低 5 元、印花税、卖出滑点和分时买点。
