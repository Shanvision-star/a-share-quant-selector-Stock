# 每日行情与目标股 Agent 闭环实施计划

> 执行方式：本会话直接实现和验证，沿用用户已经明确授权的自动更新、分析、复盘与跟踪范围。

**Goal:** 每日北京时间 18:30 更新全市场行情，使用最新已收盘交易日的数据分析配置内的目标股票，保存复盘并刷新观察跟踪，让桌面与 Codex MCP 读取同一结果。

**Architecture:** 复用现有受控更新作业、AgentRun、CSV、SQLite、Markdown 复盘。新增可独立调用的 Python 脚本与 Windows 启动入口，由当前聊天的 Codex 每日自动任务触发。脚本持久化阶段和业务 ID；失败不推进后续阶段，同交易日完成后不重复调用模型。沿用已安装桌面的 Python，不要求用户配置 Python。

**Tech Stack:** Python / 既有 FastAPI 与 Vue / stdio MCP / Codex heartbeat。

**Spec:** 用户 2026-10-23 请求及范围选择“全市场行情，再分析目标股票”；默认目标 000717 中南股份，可在配置中增删。

## 项目定位和边界

- 权威顺序：当前代码及 agent.md → 桌面工作流约定 → README → 本执行计划。此任务为编排层与 Agent 取证的代码缺口；当前交付桌面分支之上创建 `codex/daily-market-agent-chain`，不回退原功能。
- 当前代码已有全市场更新、模型研究、幂等追加复盘、MCP 和跟踪；缺少持续编排、最新日线取证与纯观察更新。
- 原“收盘同步”会推进模拟持仓，不能直接拿来实现本次观察跟踪。新增观察刷新只写最新日期/收盘、关联报告和审计事件，保留原仓位、成交、状态和意图。
- 全市场更新不自动重建全部历史策略缓存，目标 Agent 直接分析最新日线；原策略结果保留其原始日期。无钉钉发送、无交易执行。
- 完成判定必须同时满足：全市场更新业务完成且无 partial、实际目标日期一致、每只目标股 CSV 与来源都达到目标日、模型运行完成、复盘与跟踪回读一致。
- 使用北京时间和交易所日历计算最近已收盘交易日。休市日不制造新交易日；现有离线日历超出有效年份时明确失败，不能猜测未来节假日。
- 电脑及 Codex 必须运行才能按时触发。每日任务在状态不变且无问题时保持安静，只报告完成、失败或需处理事项。

## 实施与验证

- [x] 最新日线取证：增加 market 任务、日期新鲜度检查、来源哈希、界面入口和 MCP schema；用隔离 CSV 验证陈旧/未来数据/不合法目标不会进入模型。
- [x] 观察更新：显式授权与请求 ID、报告与目标绑定，事务写入与幂等回读；验证重复调用、已有持仓、失败报告和错误股票。
- [x] 每日脚本：进程锁、原子状态、阶段恢复、超时与失败保存、后台服务可用性、目标配置和 Windows 入口；验证重跑不重复模型/复盘/跟踪，partial 不推进，不跨日期混用。
- [x] 接入：桌面读取同库、MCP daily_status、界面状态；完成相关 pytest、导入 smoke、前端类型检查和 build。
- [x] 实测：使用已授权的真实全市场更新、目标模型调用、复盘、跟踪和 MCP 回读；外部数据失败时如实保留失败，不冒充最新闭环成功。
- [x] 创建每日 18:30 自动任务，记录实际调度 ID、运行条件与停用办法，更新 README 和工作流文档。

## 同轮追加的界面修复

用户指出首页缺少知行趋势线、详情短期线在白底上不可见，以及首页缺少直接搜索和切换入口。现已恢复首页两条线默认显示及开关，统一提高颜色对比与线宽；主图顶部加入全市场名称/代码搜索和上一只/下一只。候选刷新保留当前选择，空策略结果时仍保留搜索。真实桌面验证已覆盖搜索 00071、选择 000717、切换 000718 后返回及开关保持。

验收中发现同步首页检查阻塞事件循环，已改用 FastAPI 线程池；增加阻塞磁盘期间另一接口仍可响应的回归测试。自动任务已配置；此计划的完成不代表未来调度已经发生。
